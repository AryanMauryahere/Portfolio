## Visual thesis
An engineering student introduced with the confidence of an experimental design studio: enormous elegant type, precise small annotations, saturated orange, and one polished abstract orbital form. Aim for striking but readable, intentional and sparse. Avoid generic SaaS cards and dashboard styling.

## Tokens
- Primary orange: #ff5100
- Ink: #11110f
- Paper: #f2f0e9
- Secondary muted text on light: #595951
- Quiet rules: ink at 22% opacity, or paper at 24% on dark
- Display font: Bodoni Moda, Google Fonts, weight 500–600; fallback Didot, Times New Roman, serif
- Text font: Inter, Google Fonts, weights 400–600; fallback Arial, sans-serif
- Micro-labels: Inter, uppercase, 12–14px, 0.04em tracking
- Body: 17–20px, line-height 1.5–1.6
- Desktop gutters 40px (minimum 24px); mobile 20px
- Vertical rhythm: 8, 16, 24, 40, 64, 96, 128px
- Corners square; use pills only for a deliberate tiny inline topic tag, if factual
- Thin rules; no card shadows or rainbow gradients

## Motion and behavior
Natural scrolling and functioning anchor navigation. Underline or small arrow movement for links. A single slow dimensional abstract form may rotate gently or respond subtly to the pointer. Include a reduced-motion static state and never hide essential text behind animation. No sound autoplay. Keyboard-visible focus, semantic headings and nav, 44px comfortable tap targets. External links should be correct and use rel=noopener noreferrer when opening a new tab.

## Mobile
No horizontal overflow. Use clamp() sizes, allow the hero headline to scale down with a legible type silhouette. On narrow screens reduce or move the sculpture so it does not obscure headline/identity. Stack the about section; keep navigation and contact links usable. Do not treat mobile as a scaled desktop screenshot.

## Deliverable constraints
Produce one cohesive desktop draft that also responds to mobile. Do not create alternative designs. The draft is for review before implementation. Keep edits easy by grouping content, CSS design tokens and any motion logic. Future implementation must include a README for editing profile text, links, projects, styling and media.
